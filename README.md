3分钟搭建知识付费系统APP&H5：从架构选型到源码落地的专业指南
知识付费系统本质上是一套"内容—交易—交付"的闭环产品。要在3分钟内完成可运行原型，关键不在于功能堆砌，而在于架构选型精准、核心链路清晰、代码结构可扩展。

一、架构选型：速度优先
对于MVP阶段，推荐 Node.js + Express + SQLite + 原生H5 + Capacitor 组合。后端Express轻量且生态成熟，SQLite免安装、免配置，适合快速验证；前端采用原生HTML/JS单页应用，无需构建工具即可运行；APP端通过Capacitor套壳，一套H5代码可直接生成Android/iOS安装包。相比Vue+Spring Boot的重型方案，这套组合可将搭建时间从数天压缩至分钟级。

二、核心数据模型
系统只需四张表即可跑通闭环：用户表（手机号、密码、昵称）、课程表（标题、封面、价格、内容、销量）、订单表（订单号、用户、课程、金额、状态）、管理员表。关键设计在于：订单号独立生成而非自增ID，避免订单量泄露；订单状态采用pending→paid状态机，防止脏数据；课程内容与元数据分离，便于大文本和视频单独存储。

三、后端核心逻辑
后端围绕四条核心API展开：注册登录采用bcrypt加密密码、JWT签发令牌；课程列表与详情在未购买时后端不返回content字段，从源头保护内容；下单支付先创建pending订单，支付成功后更新状态并累加销量；我的课程通过订单表关联课程表查询。管理后台使用独立JWT密钥，与用户端权限隔离，提供数据看板、课程增删改查、订单与用户管理。

四、H5用户端实现
H5端采用单页路由思路，通过JavaScript切换首页、详情页、我的三个视图，无需框架即可运行。首页展示课程卡片与分类筛选；详情页根据后端返回的owned字段判断是否已购，未购买显示购买按钮，已购买直接渲染内容；我的页面展示用户信息与已购课程。登录态存localStorage，每次请求携带Authorization头。

五、APP打包
使用Capacitor执行三条命令即可出包：初始化项目、添加Android平台、同步代码并打开Android Studio生成签名APK。整个过程复用H5代码，无需重写原生逻辑。

六、生产级演进路径
MVP跑通后，需按优先级补齐：稳定性阶段引入MySQL、Redis、Nginx、HTTPS与日志监控；支付阶段接入微信JSAPI、支付宝当面付，视频托管至阿里云VOD并加HLS加密；商业化阶段补充分销、优惠券、拼团、直播；多端阶段扩展小程序与PC端。

七、合规提醒
知识付费属于经营性互联网信息服务，需办理ICP经营许可证；涉及在线教育需网络文化经营许可证；内容需接入审核服务；交易需明确退费规则；数据需符合《个人信息保护法》。这些是商用前不可逾越的红线。
